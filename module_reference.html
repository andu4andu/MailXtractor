Glossary

Module Reference

All functions across the MailXtractor codebase, organised by module in pipeline order — from reading the email to writing the final report.

readers.py Stage 1 — Email reading and body extraction
Public
read_raw_email(folder_path) public

Scans an email folder and returns all of its contents as a structured dict. The folder is expected to contain exactly one email file (.eml or .msg) and any number of sidecar attachment files alongside it.

The function iterates the folder's contents in sorted order. The first email file found becomes the email to parse; any further email files are logged as warnings and skipped. Every non-email file is collected as an attachment regardless of its extension.

.eml files are parsed with Python's built-in email module. An email is made up of multiple parts (body, attachments, etc.) and the function walks through all of them, preferring plain text for the body and falling back to HTML if no plain text part exists. Parts marked as attachments in their headers are skipped during body extraction — they are handled as sidecar files instead.

.msg files are parsed with the extract_msg library, opened in a way that automatically closes the file when done to prevent file handle leaks. The function prefers the HTML body when it contains content, falling back to the plain text body.

If no email file is found at all (an attachments-only folder), a warning is logged and the email metadata fields are all returned as empty strings.

Parameters
folder_path Absolute path to the folder representing one email. The folder name is used downstream as the correlation ID.
Returns

Dict with keys: subject, sender, recipients, date, body (raw HTML or plain text), and attachments (list of dicts, each with filename, file_type, and path).

extract_body_text(email_struct) public

Converts the raw body from an email struct into clean plain text. The body may be HTML or already plain text. Either way, the function passes it through _HTMLStripper, which extracts only the visible text content and discards all tags and attributes. The resulting string then has all runs of whitespace collapsed to a single space and is stripped of leading and trailing whitespace.

This normalised string is what gets prepended with the email header block in process_email to form the full body_string passed to the extraction engine.

Parameters
email_struct Dict returned by read_raw_email. Only the body key is read.
Returns

Plain text string with HTML tags removed and all whitespace normalised to single spaces.

Internal Helpers
_HTMLStripper internal

A minimal HTML parser used internally by extract_body_text. Extends Python's built-in HTML parser and collects every piece of visible text content while silently discarding all tags, attributes, scripts, and styles.

After feeding the HTML string in, get_text() joins all collected parts with a single space and returns the result. This avoids any external dependency for what is a straightforward stripping task.

Key methods

handle_data(data) — called automatically for each piece of visible text; appends it to an internal list.
get_text() — joins all collected pieces with a space and returns the full text string.

attachments.py Stage 2 — Attachment dispatching and text assembly
Public
handle_attachments(email_struct) public

Extracts and returns the list of attachments from an email struct. This is a thin getter that exists to give the attachments step a named entry point in the pipeline, keeping main.py readable as a sequence of named stages rather than a series of dict lookups.

Parameters
email_struct Dict returned by read_raw_email. Only the attachments key is read.
Returns

List of attachment dicts, each containing filename, file_type, and path. Returns an empty list if the email has no attachments.

spawn_attachment_workers(attachments) public

Parses all attachments in parallel using a pool of up to 4 worker threads. Each attachment is submitted as a separate background task that calls parse_single_attachment from parsers.py.

Results are collected in the same order as the input list. Each background task is waited on for up to 300 seconds — long enough to handle large ZIP archives or PPT files that need PowerPoint automation, but bounded to prevent a single stuck file from holding up the entire email.

If a background task fails for any reason (parse error, timeout, or otherwise), the error is logged and that attachment's result is replaced with an empty text string. The rest of the attachments continue processing normally — one bad file never aborts the others. Returns early with an empty list if there are no attachments.

Parameters
attachments List of attachment dicts from handle_attachments.
Returns

List of (filename, text) tuples in the same order as the input. Failed or unparseable attachments produce an empty string for their text.

combine_attachment_text(results) public

Joins the parsed text from all attachments into a single string, with each file's content labelled by its filename. Attachments that produced no text are silently skipped.

Each included section is formatted as a [filename] header on its own line, followed by the file's text. Sections are separated by a blank line. This labelling is important for downstream extraction: the per_file rule option uses these markers to split the combined string back into per-file chunks when summing values across separate documents.

Parameters
results List of (filename, text) tuples from spawn_attachment_workers.
Returns

Single string with all non-empty attachment texts joined by blank lines, each section preceded by its [filename] label. Returns an empty string if all attachments produced no text.

parsers.py Stage 3 — File-type parsers for every attachment format
Public
parse_pdf(path) public

Extracts all text from a PDF file using pdfplumber, with a per-page OCR fallback via Tesseract for pages that yield no text.

For each page, the function first finds all table regions and extracts them as pipe-delimited rows (each cell joined by _join_cell to handle multi-line cell content). It then removes those table regions from the page's word list, sorts the remaining words by vertical position and horizontal offset, and reassembles them into lines of body text.

If a specific page produces no text at all (e.g. a scanned or image-only page in an otherwise text-based document), that page alone is converted to an image and OCR-ed with Tesseract. This means a mixed PDF — some pages with selectable text, some that are scanned images — is handled correctly without losing content from either type.

Parameters
path Absolute path to the PDF file.
Returns

Extracted text string. Empty string if the file yields nothing even after OCR.

parse_xlsx(path) public

Extracts text from an XLSX spreadsheet using openpyxl, opened in a mode that reads the last calculated value of formula cells rather than the formula text itself.

Hidden sheets and sheets whose names match the skip_sheets list in config.json are silently skipped. Each remaining sheet gets a [Sheet: name] header line, followed by its rows as pipe-delimited strings. Trailing empty cells are stripped from each row; fully blank rows are omitted entirely.

Parameters
path Absolute path to the XLSX file.
Returns

Extracted text with sheet-name headers, or an empty string if the file has no visible content.

parse_xls(path) public

Extracts text from a legacy binary XLS spreadsheet using the xlrd library. xlrd is loaded on demand inside the function; if it is not installed, the function logs an error and returns an empty string instead of crashing the pipeline.

Applies the same skip logic as parse_xlsx — hidden sheets and sheets matching skip_sheets are ignored. Rows are formatted identically: pipe-delimited, trailing empty cells stripped, blank rows omitted.

Parameters
path Absolute path to the XLS file.
Returns

Extracted text with sheet-name headers, or an empty string if xlrd is missing or the file has no content.

parse_csv(path) public

Reads a CSV file and formats its rows as pipe-delimited text, using the same row structure as the spreadsheet parsers for consistency with downstream extractors.

The file is opened with a special encoding flag that silently removes the invisible marker Excel writes at the start of UTF-8 CSV exports. Without this, the first column header would have an invisible prefix and label matching would fail.

Parameters
path Absolute path to the CSV file.
Returns

Pipe-delimited text, one row per line. Empty string if the file is blank.

parse_spreadsheet(path) public

Dispatcher that routes a spreadsheet file to the correct parser based on its file extension. Exists so that callers (including parse_zip) only need to handle one function for all spreadsheet types.

Parameters
path Absolute path to the spreadsheet file (.xlsx, .xls, or .csv).
Returns

Extracted text from parse_xls, parse_csv, or parse_xlsx depending on the extension.

parse_ppt(path, powerpoint=None) public

Extracts text from both modern PPTX files and old binary PPT files, routing to the appropriate backend automatically.

The function first checks the file's format by inspecting its first four bytes. Old binary PPT files cannot be opened by python-pptx, so they are handed off to _extract_text_via_com which controls Microsoft PowerPoint directly to read the file.

For modern PPTX files, python-pptx is used. The function walks all shapes on each slide (recursing into groups via _iter_shapes) and extracts: text frame content paragraph by paragraph, table rows as pipe-delimited strings, and embedded images through Tesseract OCR.

Parameters
path Absolute path to the .ppt or .pptx file.
powerpoint Optional PowerPoint automation instance to reuse for old binary files. When not provided, _extract_text_via_com creates and destroys its own. Passed in by parse_zip to share one instance across all files in an archive.
Returns

Extracted text string with slide markers ([Slide N]), or an empty string if the file cannot be opened.

parse_zip(path, depth=0) public

Extracts and parses all supported files found inside a ZIP archive, including recursively nested ZIPs up to a maximum nesting depth of 3.

The archive is extracted to a temporary folder. The function then walks through all the files and routes each one to its appropriate parser. Unsupported file types are logged and skipped.

PowerPoint automation is started lazily — only when the first old binary PPT is encountered inside the archive — and the same running instance is then shared across all remaining presentation files to avoid the overhead of starting PowerPoint multiple times.

Both the PowerPoint instance and the temporary folder are always cleaned up when done, even if parsing fails partway through.

Parameters
path Absolute path to the ZIP file.
depth Current nesting depth, starting at 0. Archives at depth 3 or beyond are skipped with a warning to prevent zip-bomb exploitation.
Returns

Concatenated text from all supported entries, each prefixed with its filename in square brackets. Empty string if the archive contains nothing parseable.

parse_txt(path) public

Reads a plain text file and returns its contents. Used for .txt and .doc/.docx files that cannot be processed by a more specialised parser. Decoding errors are silently ignored so that files with mixed or unusual encodings do not crash the pipeline.

Parameters
path Absolute path to the text file.
Returns

File contents as a string with leading and trailing whitespace stripped.

parse_single_attachment(path, filename) public

Top-level dispatcher called by the attachment worker pool for every attachment in an email folder. Routes to the appropriate parser based on the file extension: PDF, spreadsheet, presentation, document, ZIP, or image (read directly with OCR). Files with an unrecognised extension are logged as a warning and return an empty text string — they do not crash the pipeline.

Parameters
path Absolute path to the attachment file on disk.
filename Original filename of the attachment. Used for extension detection and as the label in the returned tuple.
Returns

Tuple of (filename, extracted_text). The filename is always the original name passed in; the text is an empty string for unsupported or unparseable files.

Internal Helpers
_join_cell(cell) internal

Joins a multi-line cell string from pdfplumber into a single readable line. pdfplumber sometimes splits a single cell value across multiple lines when the PDF layout wraps text inside a cell.

The function checks each continuation part: if it is a short (≤5 character), all-alphabetic, lowercase-starting string and the previous part ended with a letter, it is treated as a word fragment and appended without a space (e.g. "suppli" + "er" → "supplier"). All other parts get a leading space.

Parameters
cell Raw cell string from pdfplumber, potentially containing newline characters.
Returns

Single-line string with word fragments rejoined and other parts space-separated.

_cell_str(cell) internal

Converts a raw spreadsheet cell value to a plain string, with special handling for numeric values. Whole-number floats like 3.0 are formatted as "3" since spreadsheets commonly store integers as floats. Values like inf or nan are handled safely to avoid crashes. Other floats are formatted to two decimal places. All other value types go through standard string conversion.

Parameters
cell Raw cell value as returned by openpyxl or xlrd — may be int, float, str, bool, datetime, or None.
Returns

String representation of the cell value, with clean integer formatting for whole-number floats.

_is_old_ppt_format(path) internal

Determines whether a file is an old binary PowerPoint file by inspecting the first four bytes of its content, rather than relying on the file extension alone. Files can be misnamed, so a bytes check is more reliable.

The check looks for the bytes D0 CF 11 E0 at the very start — the fixed identifier that marks the old Microsoft Office binary format used by all pre-2007 Office files (.doc, .xls, .ppt). Files matching this signature cannot be opened by python-pptx and must be handled via PowerPoint automation instead.

Parameters
path Path to the file to inspect.
Returns

True if the first four bytes match the old Office binary format marker, False otherwise.

_extract_text_via_com(path, powerpoint=None) internal

Extracts text, tables, and OCR content from a PowerPoint file by controlling Microsoft PowerPoint directly via Windows automation. This is the only way to read old binary PPT files.

The function opens the file by launching PowerPoint in the background, iterates through every slide, and collects: text from all text frames, pipe-delimited rows from tables, and OCR results from embedded picture shapes. Images are exported to a temporary file, read by Tesseract, then deleted immediately after.

If no PowerPoint instance is passed in, the function starts a new one and shuts it down when done. If one is passed in (by parse_zip), the caller manages the instance. On any failure, a warning is logged and an empty string is returned rather than crashing the pipeline.

Parameters
path Absolute path to the presentation file.
powerpoint Optional running PowerPoint instance to reuse. When not provided, the function creates and destroys its own.
Returns

Extracted text string with slide markers, or an empty string if PowerPoint automation fails (e.g. PowerPoint is not installed).

_iter_shapes(shapes) internal

Walks through all shapes on a slide, including shapes that are nested inside groups. In PowerPoint, shapes can be grouped together, and the text inside a group is only accessible through its individual child shapes. Without this recursive walk, text inside groups would be silently missed. Yields each individual non-group shape one at a time.

Parameters
shapes Collection of shapes from a slide, typically slide.shapes.
Returns

Individual shapes from the full shape tree, one at a time, in order.

extractor.py Stage 4 — Rule-based field extraction engine
Public
load_rules(rules_path) public

Loads and returns the extraction rules from a JSON file. The returned dict is passed directly into apply_extraction_rules() on every call, so it should be loaded once at startup and reused across all email folders rather than reloaded per email.

Parameters
rules_path Path to the JSON rules file, typically rules.json in the project root.
Returns

Dict mapping field names to their rule configuration dicts.

apply_extraction_rules(body_string, attachment_string, rules, correlation_id=None) public

The main extraction dispatcher. Iterates every field defined in the rules dict and calls the appropriate extraction helper based on the rule's type key. Returns a dict mapping each field name to its extracted string value.

Source priority. Each rule can specify source_priority to control which text is searched: "body" searches only the email body, "attachment" searches only attachment text, and "both" (the default) tries the attachment first and falls back to the body if nothing is found.

Rule types:
• auto — fills the field automatically without searching text. Supports correlation_id (set to the folder name) and date_of_input (today's date).
• empty — always returns an empty string. Used for fields that exist in the output schema but cannot be extracted.
• label — searches for a label string and extracts the value that follows it. Delegates to _extract_label. Supports optional normalize_boolean, column_values fallback, and regex_fallback.
• regex — extracts the first match of a pattern directly from the text. Delegates to _extract_regex.
• max_pattern — finds all pattern-matched numbers and returns the largest. Delegates to _extract_max_pattern.
• sum_pattern — finds all pattern-matched numbers and returns their sum. Supports per_file and year_anchored options.
• keyword_match — returns the first value from a known-values list found in the text. Delegates to _keyword_match.
• email_domain — derives the supplier name from the first external email domain found in the body. Always searches the body, regardless of source_priority. Falls back to a label search if no domain is found.

If nothing is extracted after all attempts, the rule's default value is used (empty string if not set).

Parameters
body_string Full email body string including the header block (Subject, Sender, Recipients, Date) prepended by process_email.
attachment_string Combined text from all parsed attachments, produced by combine_attachment_text.
rules Extraction rules dict loaded by load_rules.
correlation_id Optional folder name used to fill the correlation_id auto field. Falls back to a random unique ID if not provided.
Returns

Dict mapping every field name from the rules to its extracted string value.

Internal Helpers
_extract_label(text, labels, pattern=None, max_length=100, line_start=False, next_line=False, collect_lines_pattern=None) internal

The most versatile extraction helper. Searches text for a label string and returns the value associated with it. Labels are tried in order; the first match wins.

Default mode. Searches for label [any text] : value or label [any text] | value. The result is capped at max_length characters.

pattern. When set, the extracted value is validated against this search pattern before being returned. If it does not match, the next label in the list is tried.

line_start. Requires the label to appear at the beginning of a line. Prevents false matches when the label word appears inside a longer sentence elsewhere in the text.

next_line. When combined with pattern, searches the lines below the label for a pattern match instead of the same line. Returns the last match found within five lines.

collect_lines_pattern. Collects all consecutive lines below the label that match the given pattern, strips leading numbering like 1), and joins them with "; ". Useful for multi-item fields like a list of materials.

Parameters
textSource text to search through.
labelsOrdered list of label strings to try. Earlier labels take priority.
patternOptional search pattern applied to the raw extracted value. Only returns if the pattern matches.
max_lengthMaximum character length of the returned value. Default is 100.
line_startIf True, the label must appear at the beginning of a line.
next_lineIf True and pattern is set, searches the lines below the label for a pattern match.
collect_lines_patternIf set, collects all consecutive matching lines after the label and joins them with "; ".
Returns

Extracted value string, or an empty string if no label produces a match.

_extract_regex(text, pattern) internal

Searches text for the first match of a given pattern (case-insensitive) and returns it. Used for fields where the value can be found directly by pattern without needing a label to anchor it — for example, a date in a known format or a product code with a fixed structure.

Parameters
textSource text to search.
patternSearch pattern (case-insensitive).
Returns

Matched string stripped of surrounding whitespace, or an empty string if no match is found.

_extract_supplier_from_body(body) internal

Derives a supplier company name from the first external email address found in the body. Finds all email addresses, skips any whose domain is in the internal domains list from config.json, and converts the first external domain's company name segment to a readable title-cased string.

For example, an email from john@acme-solutions.com would produce "Acme Solutions". Used as a fallback when no supplier name can be found via a label in the document text.

Parameters
bodyFull email body string, including the header block where the sender address appears.
Returns

Title-cased company name string, or an empty string if no external address is found.

_keyword_match(text, values, aliases=None) internal

Searches text for whole-word occurrences of each value in a known-values list and returns the first match in its standard form. The match is case-insensitive but the returned value always uses the exact casing from the values list.

If no value from the list matches and an aliases dict is provided, it tries each alias key as a whole-word match and returns the corresponding standard value. Aliases are checked only after all list values have failed.

Parameters
textSource text to search.
valuesOrdered list of known values to match against. Earlier entries take priority.
aliasesOptional dict mapping alternative spellings to their standard values. Tried only if no list value matches.
Returns

Matched standard value string, or an empty string if nothing matches.

_normalize_boolean(value) internal

Normalises a raw label-extracted value to a clean Yes, No, or empty string. Used for fields that are essentially yes/no questions but where the source document may express the answer in many different ways.

"yes" or "y" → "Yes";
"no", "n", or "n/a" → "No";
a purely numeric string → "" (the label likely matched a numeric field by accident);
any other non-empty string → "Yes" (the presence of text implies an affirmative answer).

Parameters
valueRaw string extracted by a label rule before normalisation.
Returns

"Yes", "No", or "".

_find_year_table_sum(text, max_value=None) internal

Sums numeric volume quantities from a year-based table, handling two common layouts found in supplier documents.

Strategy 1 — column-per-year. Looks for a header row containing two or more year values (e.g. 2025 | 2026 | 2027). If found, reads the rows below and sums the numbers in the first row with valid quantities.

Strategy 2 — row-per-year. Finds lines where a year and a quantity appear on the same line separated by a pipe character (e.g. 2025 | 64,000). Sums all matched quantities.

Both strategies remove totals rows (where the last number equals the sum of all others) and duplicated column groups before summing.

Parameters
textSource text, typically from a single attachment section.
max_valueOptional upper cap. Individual values above this are excluded from the sum.
Returns

Summed volume as an integer string, or an empty string if no year table is found.

_aggregate_pattern(text, pattern, fn, max_value=None, fallback_pattern=None) internal

Generic numeric aggregation helper. Finds all pattern matches in text, converts them to numbers (handling comma-formatted values like 64,000), optionally filters out values above max_value, and applies the given aggregation function to the result set. Tries the fallback pattern if the primary yields nothing. Shared backend for both _extract_sum_pattern and _extract_max_pattern.

Parameters
textSource text to search.
patternSearch pattern whose matches are treated as numeric values.
fnAggregation function applied to the matched numbers, e.g. sum or max.
max_valueOptional upper cap. Values above this are excluded before aggregation.
fallback_patternSecondary pattern tried if the primary produces no results.
Returns

Aggregated result as an integer string. Empty string if no matches are found.

_extract_sum_pattern(text, pattern, max_value=None, fallback_pattern=None) internal

Sums all pattern-matched numeric values in the text. A thin wrapper around _aggregate_pattern with the sum function. Typically used for volume fields where multiple yearly quantities appear and need to be totalled.

Parameters
textSource text to search.
patternSearch pattern whose matches are summed.
max_valueOptional upper cap on individual values before summing.
fallback_patternSecondary pattern tried if the primary yields nothing.
Returns

Sum of all matched values as an integer string, or an empty string if no matches.

_extract_max_pattern(text, pattern, max_value=None, fallback_pattern=None) internal

Returns the largest pattern-matched numeric value in the text. A thin wrapper around _aggregate_pattern with the max function. Typically used for fields like price or size where only the highest value across multiple mentions is relevant.

Parameters
textSource text to search.
patternSearch pattern whose matches are compared.
max_valueOptional upper cap. Values above this are excluded before finding the maximum.
fallback_patternSecondary pattern tried if the primary yields nothing.
Returns

Largest matched value as an integer string, or an empty string if no matches.

_extract_column_values(text, labels) internal

Extracts all non-empty cell values from a named column in a pipe-delimited table. Used as a fallback in label rules when a field value appears as a column in a structured table rather than after a label on a single line.

Finds the first occurrence of a label as a column header, records that column's position, then reads all subsequent rows collecting the value at that position. Stops at a blank line or a file section marker. Only cells containing at least one letter are included. Multiple values are joined with "; ".

Parameters
textSource text containing a pipe-delimited table.
labelsOrdered list of column header strings to search for. Earlier labels take priority.
Returns

Semicolon-separated cell values from the matched column, or an empty string if no matching column header is found.

reporter.py Stage 5 — Gold Report Excel generation
Public
generate_excel_report(records, output_path) public

Writes all extraction results to a styled Excel workbook with two sheets — Results for emails that were processed successfully, and Failures for emails that errored or timed out.

Records are split based on whether they contain an _error key. Successful records have that internal key stripped before being written, so it never appears as a column in the output. This is done on a clean copy of each record so the original list is never modified.

Both sheets are styled via _style_sheet after the data is written. The Failures sheet is only styled if it actually contains rows.

Parameters
recordsList of dicts returned by process_email — one per email folder. Failed folders have an _error key; successful ones have extracted field values.
output_pathFull file path where the Excel workbook will be written, including filename and .xlsx extension.
Returns

Nothing. Writes the file to disk and logs the path and record counts.

Output structure
Sheet: Results One row per successfully processed email. Columns are the field names from rules.json. Header row is dark blue, bold, white text.
Sheet: Failures One row per failed or timed-out folder, with the folder name and error message. Only styled if at least one failure exists.
Both sheets Frozen top row, auto-filter on all columns, column widths auto-sized to content (capped at 50 characters).
Internal Helpers
_style_sheet(ws) internal

Applies all visual formatting to a single Excel worksheet in place. Called by generate_excel_report once per sheet after the data has been written.

Column widths. Measures the widest cell value in each column and sets the column width to match, plus small padding, capped at 50 characters.

Header row. Applies a dark blue background (#1F4E79), bold white text, and centred alignment to every cell in row 1.

Freeze and filter. Freezes the top row so the header stays visible when scrolling. Enables Excel's auto-filter so any column can be filtered or sorted without extra setup.

Parameters
wsAn openpyxl Worksheet object. Modified directly — nothing is returned.
Returns

Nothing. All changes are applied directly to the worksheet object passed in.

main.py Orchestrator — ties every module together and runs the pipeline
Public
main() public entry point

The top-level function that runs the entire pipeline. Called once when the script is executed directly.

Loads the extraction rules from rules.json, scans INPUT_PATH for subfolders (each subfolder is one email), and submits each to a pool of parallel workers. The number of workers matches the number of CPU cores on the machine, so the pipeline scales automatically to the available hardware.

Each folder is given up to 300 seconds to complete. If a folder takes longer, it is logged as a timeout error and skipped so one slow email never blocks the rest. Once all folders are done, results are handed to generate_excel_report to write the Gold Report.

Returns

Nothing. All output goes to the Excel report written to disk and to the log file.

process_email(folder_path, rules) public

Runs the full extraction pipeline for a single email folder. This is the function submitted to the worker pool by main — one call per email, running in parallel with all the others.

If anything goes wrong at any step, the error is caught, logged, and the function returns an error record instead of crashing the run.

Steps performed per email
1Read the email file and collect sidecar attachments — read_raw_email
2Strip HTML from the email body and normalise whitespace — extract_body_text
3Filter the recipients list down to external addresses only, removing any from the company's own domains
4Build the full body string: a header block (Subject, Project, Sender, Recipients, Date) prepended to the plain text body
5Parse all attachments in parallel — spawn_attachment_workers
6Join attachment texts into one labelled string — combine_attachment_text
7Run all extraction rules against the body and attachment text — apply_extraction_rules

Parameters
folder_pathAbsolute path to the email folder. The folder name becomes the correlation ID in the output.
rulesExtraction rules dict loaded once by main and shared across all parallel calls.
Returns

Dict of extracted field values on success. On failure, returns {'_error': '...', 'folder': '...'} so the reporter writes it to the Failures sheet.

get_output_path() public

Builds the file path for the Gold Report Excel file. The filename includes a timestamp taken at the moment of the call, so each run produces a uniquely named file and previous reports are never overwritten. The output directory is read from config.json or the MAILXTRACTOR_OUTPUT environment variable if set.

Returns

Full file path string in the form <output_dir>/gold_report_YYYYMMDD_HHMMSS.xlsx.

Internal Helpers
_setup_logging() internal

Sets up the logging system before the pipeline starts. Called once at the very beginning of the script, before main().

Configures two destinations for log messages: a file (run_log.txt, overwritten on each run) and the terminal. Both use the format HH:MM:SS [LEVEL] module - message. All messages at INFO level and above are captured — normal progress, warnings, and errors — but not verbose debug output.

Returns

Nothing. Modifies the global logging configuration in place.

_clean_subject(subject) internal

Strips noise from a raw email subject line to produce a clean project name. Email subjects often carry extra text unrelated to the actual project — reply/forward prefixes, internal codes, sample identifiers, and separator text added by mail clients. Six cleaning steps are applied in order:

Cleaning steps
1Remove invisible control characters that sometimes appear from certain mail clients
2Strip reply and forward prefixes — Re:, Fw:, FW:, and combinations
3Cut off anything after a --- separator (often added by ticketing systems)
4Remove sample identifiers like - Sample 1
5Remove trailing slash-separated codes such as /RFQ-001
6Remove trailing single-word suffixes like - Revised or - Final

Parameters
subjectRaw subject string from the email header.
Returns

Cleaned subject string, or an empty string if nothing meaningful remains after stripping.

Glossary

Technical terms used throughout this reference, explained in plain language.

Thread pool / parallel workers
A group of worker processes that run multiple tasks at the same time. Instead of processing emails one by one, the pool handles several simultaneously — one per CPU core — which makes the pipeline much faster on multi-core machines.
Dispatcher
A function whose only job is to look at what it received (usually a file extension or rule type) and route it to the right handler. parse_single_attachment and parse_spreadsheet are examples.
OCR (Optical Character Recognition)
Technology that reads text from images. Used when a PDF page or an image attachment contains text that cannot be selected — for example, a scanned document. The tool uses Tesseract for this.
Windows automation (COM)
A Windows technology that allows one program to control another. In this project, it is used to open old binary PPT files by launching and controlling Microsoft PowerPoint directly from Python. Requires PowerPoint to be installed on the machine.
Old binary format / format identifier bytes
Every file type has a fixed sequence of bytes at the very start of the file that identify its format — like a fingerprint. Old Microsoft Office files (.doc, .xls, .ppt made before 2007) all share the same identifier: D0 CF 11 E0. Checking these bytes is more reliable than checking the file extension, since files can be misnamed.
BOM (Byte Order Mark)
An invisible character that Excel writes at the very start of CSV files it exports. Without special handling, it appears as a garbled prefix on the first column header, which would break label matching. The CSV parser removes it automatically.
Email parts / MIME structure
An email is not a single block of text — it is made up of multiple parts: a plain text body, an HTML body, and any number of attachments. MIME is the standard that defines how these parts are packaged together. The reader walks through all the parts to find the body and skip attachment parts.
Regex (Regular Expression)
A pattern written in a special syntax that describes what to search for in text. For example, a pattern can describe "any sequence of digits followed by a comma and three more digits" to match numbers like 64,000. Used extensively in the extraction engine to find and validate values.
Pipe-delimited
A way of representing table rows as text, where columns are separated by a | character. For example, a row with three cells becomes Material | Quantity | Price. All spreadsheet and table parsers output text in this format so the extraction engine can read structured data consistently.
Correlation ID
A unique identifier that links each row in the Gold Report back to its source email folder. It is simply the folder name. This makes it easy to trace any extracted record back to the original email.
Canonical / standard value
The official, agreed-upon form of a value. For example, a field might accept "yes", "YES", or "Y" as inputs, but always outputs the canonical form "Yes". The aliases dict in keyword_match maps alternative spellings to their canonical equivalents.
Lazy initialisation
Delaying the setup of something until it is actually needed. For example, parse_zip does not start PowerPoint at the beginning — it only starts it the moment the first old binary PPT file is found inside the archive. This avoids unnecessary startup time and resource usage when no such files exist.
Zip bomb
A malicious ZIP file that contains deeply nested archives which expand to an enormous size when extracted, potentially crashing or hanging the system. parse_zip defends against this by refusing to recurse more than 3 levels deep.
